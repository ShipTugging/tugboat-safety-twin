# 디자인 개선 트러블슈팅 및 검증

## 변경 범위

2026-09-07, codex/maritime-design 브랜치. 기존 물리 Hook, 위험 임계값과 시나리오 수치는 유지했다. React/Three.js 의존성을 추가하지 않았다. 문서에 적힌 실사 모델/실시간 선박 반사는 후속 확장 항목이며 이번 구현은 기존 형상과 절차적 재질을 정교화했다.

## 원인과 함께 확인한 항목

| 현상 | 원인과 조치 | 함께 점검한 회귀 |
|---|---|---|
| 상단 오버레이 충돌 | 화면 헤더·장면 설명·하단 도구막대로 공간 분리 | 모바일, 패널 접기, 경보 표시 |
| 우측 패널 눌림 | 스크롤 컨테이너와 축소 금지 카드로 분리 | 레이더/추이/센서 탭 |
| 거대한 위험 글자가 선박을 관통 | 과거 depthTest 비활성 수정은 되돌리지 않고 텍스트를 고정 HUD로 이동 | 이전 가림 문제 재발 없이 경보 유지 |
| 파도 조명/좌표 불일치 | XZ geometry + world 좌표의 법선/시선 사용 | 주간/황혼/야간 |
| 사각 후류와 바다 교차 | 같은 해수면 shader에서 후류/포말 합성 | RPM·속력·예인선 방향 반영 |
| 컨테이너·수선 띠 교차 | 개별 적층과 선체 윤곽을 따르는 수선 띠 | 원점/단위/예인 연결점 유지 |
| 모델 재질이 어두운 덩어리로 보임 | 청회색 도장·빛 보완·측후면 창문과 선명한 갑판 디테일 | 야간 항해등 유지 |
| 예인줄 조건부 Hook | 분리 상태에서도 Hook 순서 유지, 교체 geometry 해제 | 분리 → 0kN → 재연결 |
| 레이더 화면이 녹색으로 누적 발광 | 예인줄 shadow 상태가 다음 프레임 배경까지 누출 | 매 프레임 shadow 초기화, 선 그리기 save/restore |
| 레이더에 분리된 줄이 남음 | 분리 상태 조건 없이 줄을 그림 | 분리 시 연결선 숨김 |
| 모바일 패널을 닫으면 WARNING 숨김 | 모바일 CSS에서 전역 상태를 숨김 | 모바일 상단에 상태 행 유지 |
| 후류 경계와 감지 범위 불일치 | 기존 시각 범위가 더 짧음 | 감지식 기준 Z=-35~-90, 끝 반경 15.1m로 일치 |
| 상공 시점에서 선수 잘림 | 세로 시야에 비해 카메라 높이가 낮음 | 180m 높이와 두 배 중심 타깃 |
| 기존 점검창이 항상 합격 | 시간 경과 후 고정 문자열 출력 | 실제 telemetry 기록, 원래 설정 복원, 취소 타이머 무효화 |
| 점검 시작 후 포커스 이탈 | 시작 버튼이 disabled되어 포커스 순환에서 제외 | 시작 시 dialog로 이동, Tab 트랩·Escape |

## 검증 기록

- 변경 전 물리 검사와 프로덕션 빌드 성공.
- 변경 후 타입 검사 성공. 기존 물리 검사 성공.
- 브라우저 1440×900, 1280×720, 390×844에서 주요 화면 시각 검토.
- 모바일 문서 너비 390px = viewport 390px; 가로 넘침 없음.
- 거팅 프리셋: CRITICAL, 약 78% 위험/21° 롤 관측.
- 비상 분리: 장력 0kN/거팅 위험 0; 재연결 후 장력 복귀.
- 후류 프리셋: 후류 내부/약 40% 난류 관측.
- 근접 프리셋: 약 12.5m/SAFE 관측. 원래 설명의 3.5m·CRITICAL과 다르므로 설명을 정정했으며 물리식은 변경하지 않았다.
- 시나리오 점검창: 거팅 87%/CRITICAL, 후류 약 40%, 근접 약 12.5m/SAFE, 분리 0kN을 실제 상태에서 기록. 완료 후 정상 프리셋 복원 확인.
- 점검창 실행 후 Tab 포커스가 dialog 안에 유지됨을 확인.
- 주간·황혼·야간, 자유·추적·선교·상공·시네마틱, 고품질/기본 전환 점검.
- 독립 리뷰의 모바일 경보/후류 경계/모달 포커스 지적을 반영.

개발 중 파일을 순차 교체하는 HMR 구간에 예전 컴포넌트가 새 OceanWater에 telemetry를 주지 못한 임시 오류가 기록됐다. 최종 파일 연결 후 새로고침 및 프로덕션 프리뷰에서 별도로 확인한다.

## 남은 한계

- 실제 장비별 FPS/장시간 GPU 메모리/125% 브라우저 확대/터치 실기기는 측정하지 않았다.
- 바다는 낮은 항만 파도를 표현한다. 기존 위험 엔진을 보존하기 위해 선박 운동을 새 부력 해석으로 교체하지 않았다.
- 항만은 간소화된 절차적 배경이다. 고해상도 실사 모델이나 동적 선박 반사 기능은 없다.
- 기존 물리 검사 스크립트는 앱 Hook 자체가 아닌 복사된 식을 검사하므로 브라우저 점검을 병행해야 한다.
- Vercel 프로덕션 배포/푸시는 수행하지 않았다. 비밀정보 파일은 수정하거나 추가하지 않았다.


추가 확인: 모바일 body에 남아 있던 전역 overflow-hidden을 제거하여 상세 관제 영역까지 스크롤 가능하게 했다. 상공 카메라는 +Z up-vector로 북쪽 방향을 고정해 극점 회전을 방지한다. 브랜드 파비콘을 추가하고 .env/.env.* 무시 규칙을 확인했다. 물리 Hook 변경 diff는 없다.

최종 확인: 프로덕션 빌드 성공(기존과 같은 500kB 청크 경고는 남음), git diff --check 통과. 새 프로덕션 프리뷰 브라우저의 error/warn 로그는 빈 배열이었다. 모바일에서 scrollY=844로 관제 패널까지 실제 스크롤됨을 확인했고 문서 너비 386px/viewport 390px로 가로 넘침이 없었다. 점검 실행 중 닫은 뒤 정상 프리셋 선택이 유지되어 취소 후 설정 복원을 확인했다. 프리뷰는 http://127.0.0.1:4173 에서 제공한다.
