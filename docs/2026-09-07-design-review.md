# 해양 디지털 트윈 디자인 개선 검토

작성일: 2026-09-07. 상태: 제안, 구현 전. 배포 화면 1280×720 및 현재 소스/최근 커밋을 확인했다. 다른 해상도, 모든 시나리오, 실제 FPS는 아직 검증하지 않았다.

## 목표와 추천 방향

실제 항만에서 예인 작업을 보는 듯한 바다·선박·빛을 중심으로, 필요한 위험 정보가 명확히 드러나는 관제 화면을 만든다. 기존 시나리오와 위험 계산의 의미를 보존한다.

| 방향 | 장점 | 한계 |
|---|---|---|
| 기존 화면 정돈 | 겹침과 가독성을 빠르게 개선 | 선박과 바다의 사실감 개선 폭이 작음 |
| 사실적 해양 장면 + 절제된 관제 UI (추천) | 시각적 인상과 조작성을 함께 개선 | 모델·재질·물 표현 작업 필요 |
| 영화적 연출 중심 | 발표 장면의 주목도가 높음 | 성능 비용과 조작 방해 위험이 큼 |

## 확인된 현상과 원인 후보

- 배포 화면: 상단 좌우 오버레이가 겹쳐 상태 문구가 가려진다. 본선이 화면 밖으로 크게 잘리고 예인선과의 관계가 잘 드러나지 않는다. 비전 패널 내용이 눌리고 우측 문구가 과도하게 줄바꿈된다.
- `App.tsx`: 데스크톱 54:46 고정 비율, 작은 화면에서 상하 반분. 화면 크기에 따른 정보 밀도 조정이 필요하다.
- `Scene3D.tsx`: 양쪽 상단에 독립 absolute 영역을 배치한다. 조작 메뉴의 폭 제한은 장면 컨테이너가 아니라 전체 viewport 기준이다.
- `Dashboard.tsx`, `VisionAIFeed.tsx`: 세로 flex와 overflow-hidden 조합에서 패널 축소 가능성이 있다. 최소 높이, shrink 정책, 스크롤 영역을 검증해야 한다.
- 기존 커밋 `4c04092`는 선박에 가려지는 위험 글자를 20~32m 높이고 depthTest를 꺼서 해결했다. 단순 복원하면 이전 가림 문제가 돌아온다. 대신 화면 좌표 기반 라벨 배치, 충돌 회피, 가려짐에 따른 축약 표시가 필요하다.
- `OceanWater.tsx`: XY 평면을 회전하면서 파도는 로컬 XZ/Y 기준으로 계산한다. 시선은 뷰 좌표, 법선은 로컬 좌표여서 조명 계산 기준도 불일치한다. 밤에도 하늘 반사 색은 낮의 상수다. 좌표계·법선·시간대 일관성을 먼저 검토한다.
- 선박 상하 움직임과 해수면은 서로 다른 식을 사용한다. 파도만 키우면 선체 침수/부유 및 항적 분리 현상이 생길 수 있다.
- `LargeShip.tsx`: 컨테이너가 큰 단색 상자로 구성되고 상단 REEFER도 별도 적층 높이 없이 같은 배치식에 들어간다. 곡선 선체에 직사각형 수선 띠가 있어 돌출 가능성이 있다. 형상 교차를 점검한다.
- `useMaritimePhysics.ts`는 프레임에서 React 상태를 갱신한다. `TowingLine.tsx`는 변하는 끝점으로 형상을 다시 만든다. 고품질 효과 추가 전 업데이트/할당 비용을 측정한다.
- `TowingLine.tsx`는 quick release 조건부 반환 뒤에 Hook이 있어 Hook 호출 순서 위험이 있다. 비상 분리/복귀는 별도 회귀 확인 대상으로 둔다.
- 비전 피드는 합성 UI이고 신뢰도도 시뮬레이션 값이다. 실제 카메라/추론 결과처럼 보이는 문구를 구분한다.

## 디자인 구성

1. 넓은 3D 장면과 접을 수 있는 약 320~380px 정보 패널. 상단은 상태와 뷰 설정, 하단은 시나리오와 주요 조작. 비상 분리는 스크롤 없이 접근한다. 좁은 화면에서는 상세 정보를 탭/접이식 영역으로 전환한다.
2. 기본 장면은 자연스러운 청록 바다, 낮은 항만 파고, 부드러운 수평선 안개. 격자와 큰 위험 벽은 분석 모드에서 제공한다. 실제 경보 요약은 모든 모드에서 유지한다.
3. 실제 참고 자료에 맞춘 선체 비례와 수선, 곡면 방충재, 유리, 도장, 갑판, 로프. 최적화된 GLB 모델 또는 기존 형상 개선을 비교한다. 모델을 바꿔도 물리 좌표/예인 연결점은 어댑터로 보존한다.
4. 일관된 태양 방향·하늘·반사·노출. 포말과 후류는 속력/RPM/방향에 연결하고 선박과 같은 파도 기준을 사용한다. 실시간 선박 반사는 품질 상위 옵션으로 실험한다.
5. 네이비/슬레이트 기반, 흰 본문, 청록 선택 상태, 주황 주의, 빨강 위험. 한국어 본문은 읽기 쉬운 서체, 수치에는 고정폭 숫자. 정상 상태의 점멸과 발광을 줄인다.
6. 선택 선박 라벨과 핵심 거리만 기본 표시. 겹치는 라벨은 묶거나 옆으로 이동하고 연결선으로 대상을 표시한다. 화면 밖 표적은 가장자리 마커로 안내한다.
7. 발표용 시네마틱과 조작용 관제를 구분한다. 장면 전환은 사용자가 중단 가능해야 하며 카메라 전환 중에도 경보와 비상 조작을 유지한다.

## 예상 문제와 대응

| 문제 | 대응 |
|---|---|
| 고해상도 재질·반사·그림자로 버벅임 | 기준 기기에서 먼저 측정, 품질 단계와 해상도 상한, 반복 물체 공유/인스턴싱 |
| 모델 다운로드가 느림 | 모델/텍스처 압축, 단계 로딩, 실패 시 기존 모델 대체, 라이선스 확인 |
| 반투명 바다·포말·위험 영역 정렬 오류 | 재질별 깊이 정책과 렌더 순서 검증; z-index/순서값 일괄 증가는 피함 |
| 새 모델과 예인줄·거리·위험 영역 불일치 | 단위/축/원점/연결점 계약, 기존 물리 계산 보존 |
| 시각적 파도 수정으로 위험 계산 변경 | 시각 운동과 위험 판정 구분, 결합 변경은 별도 검증 |
| 패널 수정으로 화면 조작 차단 | 포인터 영역과 스크롤 경계 확인, 비상 버튼 상시 접근 |
| 자동 카메라가 배 안으로 진입 | 선박 경계 기반 카메라 거리/타깃, 전환별 확인 |
| 화려한 경보로 대상/본문 가림 | 상태 우선순위와 노출 개수 제한, 색 외 텍스트/아이콘 병행 |
| 배포에서만 에셋 로딩 실패 | Vercel 프리뷰에서 경로/디코더/외부 요청 검증 |

## 진행 순서와 완료 기준

1. 현재 네 시나리오·카메라 다섯 모드·시간대 셋을 기준으로 기록하고 기존 물리 테스트/빌드를 확인한다.
2. 겹침, 패널 축소, 기본 카메라 구도와 정보 우선순위를 먼저 정돈한다.
3. 바다 좌표계와 조명 일관성을 수정하고 선체/수면/항적 연결을 검증한다.
4. 선박 재질·형상과 항만 배경을 보완한다.
5. 선택적 반사·후처리·시네마틱을 추가하고 성능을 조정한다.
6. Vercel 프리뷰 검토 후 배포한다. 트러블슈팅에 변경 원인과 동반 회귀 항목을 기록한다.

검토 해상도: 1920×1080, 1440×900, 1280×720, 390×844, 브라우저 확대 125%. 목표는 주요 조작/라벨의 겹침 없음, 비상 분리와 복귀 정상, 선박 두 척의 관계가 보이는 초기 구도다. 성능은 선정한 기준 PC에서 60fps, 저사양 품질에서 30fps를 목표로 삼되 아직 측정 결과는 없다.
