# 합성 데이터 검증 / 트러블슈팅

## 구현

- 기존 물리 Hook에서 순수 `stepMaritimePhysics` 엔진 분리. 원래 Hook의 1,200 연속 프레임과 동일한 출력 비교 완료. 라이브와 캡처가 같은 식을 사용하되 상태는 독립적이다.
- 캡처는 샘플마다 가상 120프레임(2초) 동안 롤을 안정화한다. 샘플을 React에 반영하고 두 R3F 프레임 후 최종 렌더 단계에서 960×540 렌더 → JPEG 추출 → 동일 카메라/메시 라벨 계산을 연속 실행한다.
- `preserveDrawingBuffer: true`, 독립 캡처 카메라, renderer 크기·DPR 복원. UI와 분석 경계, 위험 색상/경광등은 학습 이미지에서 제외한다.
- 거품은 고정 수명 4초, 45RPM에서 20개/초·크기 0.4m, 115RPM에서 40개/초·0.8m. 45 미만은 꺼지고 115 이상은 상한 고정. 부드러운 원형 반투명 point sprite.
- 수면은 외부 파일 없이 256² seamless gradient-noise normal map을 생성한다. 두 회전 UV/서로 다른 크기/드리프트와 mipmap으로 반복 무늬를 줄였다. 해무는 FogExp2 및 수면/거품 shader 동일 밀도·색으로 적용한다.
- `TUG_AFT_DECK`: 예인선 선미 덱 좌측 CCTV. `TUG_BRIDGE`: 조타실 내부 80° 광각. 예인선 회전/기울기를 반영하며 선미·줄을 향한다. 야간 실제 선미를 향하는 투광등 추가.
- ZIP 생성은 지연 로딩한 JSZip/FileSaver로 처리. 1~500장, JPEG 데이터 150MiB 제한, 진행률, 취소, 30초 렌더 타임아웃, 재다운로드 제공.

## 해결한 문제

| 문제 | 조치 |
|---|---|
| React 상태를 바꾼 직후 이전 메시가 캡처될 수 있음 | 샘플 ID와 렌더 대기 확인 후 프레임 끝에서 촬영 |
| 카메라 뒤의 Box3 꼭짓점이 뒤집힌 거대 라벨 생성 | near/far 평면에서 12개 모서리 교차를 자른 후 화면 투영 |
| CCTV 자선이 화면 전체 라벨이 됨 | 선내 CCTV에서 자선 클래스 0 제외 |
| 선미 클래스가 전체 상선을 포함 | 실제 상선 Box3를 aft 구역으로 제한 |
| 줄의 라벨과 모양 불일치 | 공용 `getTowlineState`로 곡률/클래스 동시 결정 |
| 줄 연결점이 기울어진 갑판을 벗어남 | 실제 윈치/초크 위치와 선체 변환에 맞춘 시각 연결점 |
| 캡처용 카메라가 사용자의 조작 구도를 덮음 | 캡처는 독립 카메라만 사용, 라이브 카메라/OrbitControls는 제자리에서 정지 |
| normal map의 정렬된 반복 무늬 | seeded gradient-noise, 서로 다른 UV 회전/배율 및 mipmap |
| Fast Refresh에서 이전 normal texture가 남음 | 최종 검사와 배포 검증은 새로 로드한 화면에서 수행 |
| 중간 취소 후 다운로드/상태 변경 위험 | AbortController 및 타이머 정리, 부분 ZIP 다운로드 금지 |

## 검증 결과

- 단위 검사 30개 통과: 실제 물리 상태, 네 프리셋, 분리, 결정성, 투영/클리핑, YOLO 직렬화, 45/115RPM, 현수선, 카메라, ZIP 페어.
- 기존 `npm run test:physics` 통과.
- 브라우저 6장 시험 ZIP, 이후 100장 ZIP 생성 및 실제 다운로드 확인.
- 최종 100장 ZIP: 6,872,303 bytes; JPEG 100 / TXT 100; 모두 960×540; JPEG 디코딩·비검은 프레임·클래스/좌표 범위·프레임명·metadata 페어 검사 통과.
- 시드 1043의 클래스 수: Tugboat 34 / Taut 47 / Slack 50 / Stern 87. 라벨 없는 음성 표본 3장. CCTV 자기 배 제외와 조타실 FOV 80 확인.
- 장수 0 입력 오류 확인. 500장 작업의 51번째 프레임 부근 취소 후 원래 조작 카메라와 6kn/32m 운항 값 유지.
- 브라우저 WebGL/JavaScript error/warn 없음.
- 모바일 390×844: 생성 UI 가로 넘침 없음(문서 386px). 3장 ZIP 생성/다운로드 성공. 캡처 해상도는 모바일에서도 960×540 유지.
- 거품의 화면 크기는 `onBeforeRender`에서 실제 렌더 카메라/FOV/버퍼 크기로 계산하므로 독립 캡처 카메라에서도 물리 크기 비율이 유지된다.

## 라벨 정책과 한계

Box3 투영 방식은 부분 가림에서도 전체 경계상자를 사용하므로 특히 카메라 가까운 대각선 예인줄의 라벨이 넓을 수 있다. 샘플 표면 raycast로 완전 가림을 보수적으로 제거하지만 정밀 가시 면적/분할 마스크는 아니다. 짙은 안개·야간 시각 식별성은 실제 학습 전에 검토해야 한다. 도메인 무작위화는 현실 데이터 기반 검증이나 실제 학습 성능의 증명을 대체하지 않는다.

다운로드 ZIP과 검토용 이미지들은 저장소 밖에서 검사했으며 Git에 포함하지 않는다. `.env` 및 키 파일은 커밋/배포 대상에서 제외한다.
