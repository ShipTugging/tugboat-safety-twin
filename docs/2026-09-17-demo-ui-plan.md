# TUG GUARD 시연 화면 개선 기획

- 작성일: 2026-09-17
- 상태: 구현 완료, 배포 검증 진행
- 기준 코드: `be3f8fc` — 선수 기준 기본값 및 거팅 시나리오 반영
- 목적: 배와 예인줄의 움직임, AI 감지 결과, 위험 판단 이유를 한 화면에서 확인하고 쉽게 조작한다.

## 1. 현재 문제

1280×720 화면에서 하단 상세 설정이 큰 높이를 차지하여 배 화면이 얇게 눌린다. 오른쪽 운항 모니터에는 서버 연결, 데이터 생성, 선박 소개, 위험 수치와 여러 탭이 함께 있어 시연 중 필요한 정보를 찾기 어렵다.

| 확인 항목 | 문제 | 개선 방향 |
|---|---|---|
| 하단 상세 설정 | 배 화면 높이를 과도하게 사용 | 오른쪽 조작 패널로 이동 |
| 서버 연결 | 하단과 오른쪽에 주소·연결·초기화 중복 | 한 곳에서 연결과 상태 관리 |
| 카메라·운항 조절 | 같은 기능이 여러 위치에 반복 | 조작 위치 통합 |
| 위험 표시 | 서버 판정과 시뮬레이션 위험 백분율 혼재 | 기본 화면은 서버 판정 중심 |
| 상태명 | 영문과 어려운 한국어가 혼재 | 공통 한국어 표시 규칙 적용 |
| 연구·개발 기능 | 데이터셋과 로그 도구가 기본 화면에 노출 | 추가 도구로 이동 |
| 시나리오 이름 | 프리셋 이름을 실제 판정으로 오해 가능 | 입력 조건과 분석 결과를 구분 |

점검 당시 프론트엔드 테스트 95개와 빌드는 통과했다. Python 서버는 연결 거부 상태였으므로 이번 UI 점검에서 최신 서버의 실시간 판정은 재검증하지 않았다. 기능이 불필요한지와 기능이 고장 났는지는 구분한다.

## 2. 화면 구성

왼쪽은 배와 예인줄 화면, 오른쪽은 실시간 분석과 조작으로 구성한다. 기존 하단의 큰 설정창은 제거하고 오른쪽으로 통합한다.

```text
┌───────────────────────────────────────────────────────────────┐
│ TUG GUARD                  추가 도구 · 설정 · 예인줄 분리      │
├──────────────────────────────────────┬────────────────────────┤
│                                      │ 실시간 분석             │
│                                      │ [주의] 판단 이유        │
│                                      │ 감지 상태 · 사용 정보   │
│         배 · 예인줄 화면              │ CCTV + 예인줄 감지 표시 │
│                                      │ 처짐 · 기울기 · 변화    │
│         선수 기준 기본 시점           ├────────────────────────┤
│                                      │ 시나리오 선택           │
│                                      │ 예인선 방향             │
│                                      │ 예인줄 길이             │
│                                      │ 큰 배 속도              │
│                                      ├────────────────────────┤
│ [줄 감시] [전체 보기]                 │ 분석 시작/중지 · 연결   │
└──────────────────────────────────────┴────────────────────────┘
```

### 배치 원칙

- 데스크톱에서 배 화면은 가용 너비의 약 70~75%, 오른쪽 패널은 약 25~30%를 사용한다.
- 오른쪽 패널은 1280px 화면에서 약 340~380px를 확보하고, 넓은 화면에서는 약 400px까지 사용한다. 비율보다 조작 가능성을 우선한다.
- 1280×720에서 배 화면 높이 540px 이상을 목표로 한다. 헤더를 제외한 세로 공간을 주로 장면에 배정한다.
- 오른쪽 기본 패널에서 현재 판정, CCTV, 주요 조절, 분석 시작/중지를 스크롤 없이 확인한다.
- 좁은 화면에서는 장면 위·패널 아래의 세로 배치로 전환한다. 모바일까지 무리하게 한 화면에 압축하지 않는다.
- 배 영역 확대는 우선 레이아웃으로 해결한다. 카메라를 무조건 확대해 예인줄 끝이 잘리지 않도록 한다.
- 서버가 분석하는 CCTV와 사용자가 보는 전체 장면을 명확히 구분한다. 전체 보기로 전환해도 서버 입력은 고정 CCTV임을 표시한다.

## 3. 실시간 분석 패널

정보 순서는 현재 위험 단계 → 판단 이유 → 예인줄 감지 영상 → 핵심 수치로 고정한다.

1. **현재 상태:** 큰 한국어 단계명과 색상·아이콘을 함께 표시한다.
2. **판단 이유:** 서버가 반환한 근거를 쉬운 문장으로 표시한다. 예: “줄 처짐이 빠르게 줄고 있습니다”, “배 기울기가 기준을 넘었습니다”.
3. **감지 상태:** 예인줄 감지됨 / 감지 불안정 / 감지되지 않음을 위험 단계와 별도로 표시한다.
4. **판단에 사용한 정보:** 영상 + 기울기 센서 / 기울기 센서 중심 / 기울기 센서만으로 표시한다.
5. **감지 영상:** 해당 응답과 같은 프레임의 CCTV에 YOLO 마스크를 겹친다.
6. **핵심 수치:** 줄 처짐 비율, 처짐 변화 속도, 배 기울기를 우선 노출한다. 영상 각도와 기울기 변화 속도는 상세 정보에서 확인한다.

미검출 상태에서도 기울기 센서로 위험이 판정될 수 있다. 예를 들어 “매우 위험 · 예인줄 감지되지 않음 · 기울기 센서만 사용”을 함께 표시한다. 연결 중지나 오류 후 남아 있는 수치는 반드시 “마지막 결과”와 경과 시간을 표시하며 현재 분석 결과처럼 보이지 않게 한다.

## 4. 위험 단계 한국어 표시

API와 저장 파일의 상태 코드는 유지하고 화면 표기만 공통 함수로 변환한다.

| 서버 코드 | 기본 표시 | 설명 |
|---|---|---|
| `Normal` | 정상 | 현재 입력이 시연용 위험 기준 이내 |
| `Loaded` | 줄 팽팽함 | 영상에서 줄 처짐이 작은 상태 |
| `GirtingRisk` | 주의 | 위험 징후가 확인된 상태 |
| `Developing` | 위험 | 더 높은 위험 기준에 도달한 상태 |
| `Critical` | 매우 위험 | 가장 높은 위험 단계가 확인된 상태 |
| `UNKNOWN` | 판단할 정보 부족 | 현재 정보로 위험 단계를 판단하기 어려움 |

`Loaded`는 장력 센서 측정값이 아니므로 “인장 하중 감지”로 표현하지 않는다. `Normal`은 안전 보증을 뜻하지 않는다. 시연용 정책이라는 설명은 도움말에 간결하게 유지한다.

## 5. 용어 정리

| 현재 표현 | 화면 표현 | 표시 위치·주의점 |
|---|---|---|
| 운항 모니터 | 실시간 분석 | 오른쪽 패널 제목 |
| 조향각 | 예인선 방향 | 도 단위와 방향 표시 유지 |
| 본선 속력 | 큰 배 속도 | 단위 kn 유지, 도움말에 노트 설명 |
| 예인줄 | 예인줄 길이 | 입력값의 의미 명확화 |
| 추진기 RPM | 프로펠러 회전 속도 | 고급 설정에 이동, RPM 단위 유지 |
| Sag / SagRatio | 줄 처짐 비율 | 줄 처짐 ÷ 양끝 거리 설명 제공 |
| Sag 변화율 | 줄 처짐 변화 속도 | 감소할 때 “줄이 팽팽해지고 있습니다” |
| Roll / 횡경사 | 배 기울기 | 도 단위 유지 |
| Roll rate | 기울기 변화 속도 | 상세 정보, °/s 유지 |
| 영상 각도 | 화면 속 줄 각도 | 실제 3D 예인각과 구분 |
| 초기 대비 각도 | 처음보다 바뀐 줄 각도 | 상세 정보 |
| 신뢰도 | 예인줄 감지 신뢰도 | 위험 확률로 표현하지 않음 |
| 융합 | 판단에 사용한 정보 | 영상·기울기 센서 조합을 한국어로 표시 |
| 거팅 | 예인줄에 의한 전복 위험 | 도움말에서 전문용어 병기 |
| 초기화 | 목적에 맞는 명칭 | 장면 초기화 / 분석 기록 초기화 구분 |
| 비상 분리 | 예인줄 분리 | 분리 후에는 예인줄 다시 연결 |

감지 신뢰도는 서버 필드의 실제 정의를 확인한 뒤 적용한다. 감지되지 않은 경우 0%를 임의로 만들지 않고 “측정 없음”으로 표시한다.

단축키는 유지할 수 있다. 같은 기능의 화면 버튼 중복만 줄이며, 숫자 입력 중 단축키가 개입하지 않는 기존 동작을 보존한다.

## 7. 시연 흐름

1. 페이지를 열면 선수 기준 줄 감시 장면이 표시된다.
2. 오른쪽에서 분석 시작을 누른다. 최초 연결 또는 연결 실패 시 서버 주소 설정을 연다.
3. 기본 운항 조건으로 시작하고 초기 기준 수집 상태를 표시한다.
4. “방향 크게 변경” 등의 조건 프리셋 또는 직접 입력으로 줄·기울기 변화를 만든다.
5. 실제 서버 응답에 따라 한국어 위험 단계와 판단 이유가 바뀐다.
6. 예인줄 분리 후 감지 상태와 위험 회복 여부를 관찰한다. 분리 즉시 정상으로 강제 변경하지 않는다.
7. 새 실험에서는 장면 초기화와 분석 기록 초기화를 구분해 수행한다.

프리셋은 설정값을 적용하는 기능이다. 특정 위험 결과를 보장하는 이름이나 강제 판정을 사용하지 않는다. 높은 위험을 재현하는 조건은 실제 서버 연동 검증 후 설명에 기록한다.

## 8. 구현 범위와 회귀 방지

이번 작업은 화면 배치, 표시 문구, 기능 진입점 정리에 집중한다. 물리 엔진, 모델 체크포인트, 서버 위험 임계값, 이미지·IMU 동기화 및 내보내기 형식은 변경 대상이 아니다.

- 상태 번역은 공통 모듈로 관리해 하단·상세·경고에 서로 다른 문구가 나오지 않게 한다.
- 패널 이동으로 서버 분석 훅이 중복 실행되거나 탭 전환 때 세션이 초기화되지 않게 한다.
- 데이터 생성 중 분석 일시 중지와 완료 후 복원 흐름을 보존한다.
- 화면 크기가 바뀌어도 서버 입력 CCTV의 960×540 캡처와 마스크 정렬을 보존한다.
- 기존 문제 기록 중 선수 기본값 복귀, 시나리오에 따른 위치 변경, LAN 세션 ID, 오래된 서버 결과 표시, 위험 회복 지연을 회귀 확인한다.
- 접속 실패는 서버 미실행·주소 오류·네트워크 문제를 구분할 수 있도록 짧은 안내와 설정 진입점을 제공한다.

## 10. 작업 순서

1. 메인 레이아웃을 배 화면 + 오른쪽 패널로 재구성한다.
2. 중복 조작을 통합하고 기본·고급·추가 도구의 진입점을 정리한다.
3. 한국어 상태명과 쉬운 용어를 공통 적용한다.
4. 실제 서버 결과를 중심으로 분석 카드와 감지 영상을 배치한다.
5. 화면 크기별 UI와 서버 연동·기존 내보내기 기능의 회귀를 확인한다.
6. 검증 기록과 README를 갱신한다.

## 추가 반영

카메라 이름을 CCTV 예인줄 감시로 통일하고 선택창을 확대했다. 화면 설정 버튼은 항상 같은 위치에서 열고 닫으며 패널만 위로 펼쳐진다. 조작 숨기기/표시도 고정 위치를 사용한다. 장식용 하단 영문 문구를 제거했다. 추가 도구와 모바일 화면은 필요 시 스크롤을 사용한다.
